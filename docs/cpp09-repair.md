# CPP09 評価指摘への修正と検証

日付：2026-10-01。対象：`cpp09/ex00`〜`ex02`。手元の subject Version 3.3 と、今回受け取った評価指摘に基づく。

## 2026-10-06 の追加修正

- ex00 の引数・ファイル・DB エラーを共通仕様どおり stdout に統一した。回帰テストは stdout のエラーと stderr が空であることを確認する。
- RPN の表示を `digits10 + 2` の 17 桁にした。旧表示は、double が正確に保持する `9^16 = 1853020188851841` を `1853020188851840` に丸めていた。CLI とバッチの `9^11`〜`9^16`、6912・5・−1.5 を Decimal で厳密照合する。
- RPN の基底コンテナを `std::list<double>` に明示指定した。演算は stack API のまま、ex02 の deque と基底型でも重複しない。

ex02 は各時間行に `comparisons`・`pair_swaps`・`insertions` を追加し、4 行出力を維持した。全再帰段階の値比較、ペアの局所添字交換、pending 要素の `chain.insert` を数える。初期 chain の push、コンテナの swap、STL 内部の移動は含めない。ソートごとに集計を作り直し、成功した入力の読込で両方の集計をリセットする。コピー・代入では集計も保持する。

統合後の macOS 通常版は 12,939 assertions 成功。PmergeMe の 439,643 ケースで整列・比較回数上界・独立計測との一致・挿入回数を確認し、CLI の手計算 7 パターンと API の再利用も成功した。

`./PmergeMe 3 5 9 7 4` は両コンテナとも `comparisons: 7 | pair_swaps: 2 | insertions: 2` を表示する。計測時間にはカウントの加算処理も含まれ、この検証から速度の優劣は判断しない。

## 原因と修正

| 対象 | 原因 | 修正後 |
|---|---|---|
| ex00 | double への変換で `1000.0000000000000000000001` が 1000 に丸められ、上限超過を見逃す | 変換前の十進文字列で符号と 1000 との大小を判定。先頭ゼロ・小数点・指数表記も扱う |
| ex01 | int のスタックと整数除算が途中の小数を切り捨てる | 当時は `std::stack<double>` のみを宣言し、演算・戻り値・表示まで double を保持。list の指定と整数へのキャストを削除。基底の list 指定は上記 2026-10-06 の追加修正で復活 |
| 回帰テスト・解説 | `5 2 / 2 *` の結果を 4 として検査し、整数除算を正しい設計として説明していた | 期待値を 5 に修正。評価指摘の 6912 と、Fraction による独立した正解との照合を追加 |
| ex00・ex01 | 非ゼロ値の乗除算が表現範囲を下回ると、0 を正常結果として出す | ゼロへのアンダーフローを明示的なエラーにする。実際の 0 は正常に扱う |

ex00 は追加済みの検証関数が呼ばれておらず、作業開始時の `-Werror` ビルドが unused-function で失敗した。関数を入力処理へ統合した。DB の空・不正・重複日付・読込失敗も検出し、再読込は完全な検証の成功後に入れ替えるため、失敗時に既存 DB が部分更新されない。

追加した指数処理は最終確認で `1e4`・`.1e5`・`.01e6` の誤受理を発見し、飽和上限を文字列長 + 4 に修正した。短い仮数と指数 403 通りを回帰テストに加え、別の監査で 17,745 ケースの字句判定を確認した。

ex02 の Ford–Johnson 実装は、独立監査で不具合を確認しなかったため維持した。ペア対応は値ではなくインデックスで保持し、勝者を再帰的に整列し、敗者と奇数の余りを同じ Jacobsthal 順で挿入する。敗者の二分探索は相手の勝者より前に限定する。

Linux の最終変更後の再実行は、変更のあった ex00 に限定した。ex01・ex02 は同じソースで成功している結果を採用した。ホストのリポジトリを read-only でマウントし、コンテナ内のコピーを検証した。検証用コンテナは終了後に削除済み。

比較回数の監査は一時コピーの private ヘルパーを公開し、値の比較箇所のみを数える。2026-10-06 以降は本体にも処理回数カウンターを持たせ、テスト側の独立計測と照合する。テスト専用 API と std::sort は提出実装に追加しない。CLI でも別途 Python `sorted` と照合する。詳細と公開参考資料は [テスト説明](../tests/cpp09/README.md) にまとめた。

## 検証の境界

- 修正済みコードの自動検証と独立レビューの結果であり、正式な再評価の合格を示すものではない。
- 範囲判定は十進文字列に対して厳密。換算と RPN の計算自体は double の精度で行う。非有限値とゼロへの全桁消失は拒否する。
- 10 要素以上の全順列や、実ディスクの途中読込エラー注入は実行していない。大量入力は固定・生成ケースで確認した。
- CPP05〜CPP09 の共通スクリプトは push 前に再実行した。CPP00〜CPP04 の再検証と、他モジュールの新たな仕様監査は行っていない。
